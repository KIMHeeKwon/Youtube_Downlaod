## 1. 투어 문안 및 단계 구성 — 가장 바뀌기 쉬움

현재 [[gui.py]] 위젯 구성을 기준으로 4단계. 문안은 **"이 앱으로 무엇을 어떻게 하는가"**의
전체 그림을 주는 데 초점을 둔다 (위젯 조작법 설명이 아님).

| # | 대상 위젯 | 제목 | 본문 |
|---|-----------|------|------|
| 1 | URL 입력란 | 주소를 붙여넣으세요 | YouTube에서 복사한 주소를 여기에 붙여넣습니다. 영상 하나는 물론 재생목록·라이브 다시보기 주소도 그대로 넣으면 됩니다. |
| 2 | 해상도·코덱·자막 (3개 위젯 묶음) | 옵션은 건드리지 않아도 됩니다 | 기본값으로 두면 그 영상에서 받을 수 있는 **가장 좋은 화질**로 저장됩니다. 오래된 기기에서 재생하려면 코덱을 `compat`으로, 자막이 필요하면 `ko,en`처럼 언어를 적으세요. |
| 3 | 다운로드 버튼 | 누르면 시작됩니다 | 진행률과 속도가 아래 막대에 표시됩니다. 화질이 높을수록 시간이 걸리며, 창을 닫지 않고 기다리면 됩니다. |
| 4 | 저장 폴더 열기 버튼 | 받은 영상은 여기에 | 다운로드가 끝나면 이 버튼으로 저장 폴더를 엽니다. 파일은 `downloads` 폴더에 `제목 [영상ID].mp4` 형식으로 저장됩니다. |

- 2단계는 위젯 3개를 한 번에 비춘다 → 스포트라이트 사각형은 **세 위젯 bounding box의 합집합**.
- 말풍선 하단: `● ○ ○ ○` 진행 표시 + `[건너뛰기]` `[다음]` (마지막 단계는 `[시작하기]`).

## 2. 업데이트 UI 노출 방식 — 사용자 대면

### 2.1 yt-dlp 자동 갱신 (D3, 무인)
- 앱 시작 직후 **백그라운드 스레드**에서 수행. UI를 막지 않는다.
- 상태 표시는 로그 영역 한 줄로만: `yt-dlp를 최신 버전으로 갱신했습니다 (2026.7.4 → 2026.8.1)`.
- 실패(네트워크 차단 등) 시 **조용히 무시**한다 — 기존 버전으로 계속 동작하므로 사용자에게
  알릴 실익이 없다.

### 2.2 앱 본체 업데이트 (D3·D4, 원클릭)
- 시작 시 백그라운드로 GitHub Releases 최신 태그 조회 (타임아웃 3초, 실패 시 무시).
- 새 버전이 있으면 **창 최상단에 배너 한 줄**을 삽입:

```
┌────────────────────────────────────────────────────────┐
│ 새 버전 v0.2.0이 나왔습니다.   [업데이트]  [나중에]      │
└────────────────────────────────────────────────────────┘
```

- `[나중에]` → 해당 버전은 이번 설치본에서 다시 알리지 않는다 (설정에 `skip_version` 기록).
- `[업데이트]` → 진행 창(다운로드 → 검증 → 교체 → 재시작)을 띄우고 §5 절차 수행.

## 3. 신규 모듈 공개 인터페이스

### 3.1 `tour.py` — 오버레이 투어 (~130줄 예상)

```python
@dataclass
class Step:
    widgets: list[tk.Widget]   # 스포트라이트 대상 (복수면 합집합)
    title: str
    body: str

class Tour:
    def __init__(self, root: tk.Tk, steps: list[Step]) -> None: ...
    def start(self) -> None: ...        # 1단계부터 표시
    def close(self) -> None: ...        # 모든 오버레이 창 파괴
```

**4분할 딤 패널 구현 규칙** (D6):
- 오버레이는 `Toplevel` 5개 — 딤 4개(상·하·좌·우) + 말풍선 1개.
- 딤 창: `overrideredirect(True)`, `-alpha 0.55`, 배경 `#000000`, `-topmost True`.
- 타깃 사각형은 `widget.winfo_rootx/rooty/width/height`로 계산 (화면 절대 좌표).
  여러 위젯이면 min/max로 합집합을 구하고 여백 6px을 준다.
- 단계 전환 시 창을 새로 만들지 않고 `geometry()`만 갱신 → 깜빡임 방지.
- 부모 창 이동/크기 변경 중 좌표가 어긋나는 문제는 **투어 중 부모 창을 `resizable(False)`**로
  두는 보수적 선택으로 회피한다 (투어 종료 시 원복).

### 3.2 `updater.py` — 갱신 (~110줄 예상)

```python
CURRENT_VERSION: str            # pyproject.toml의 version 필드에서 읽음

def update_ytdlp() -> tuple[str, str] | None:
    """yt-dlp를 최신으로 갱신. (이전, 이후) 버전 튜플 또는 변화 없으면 None."""

def check_app_update(timeout: float = 3.0) -> Release | None:
    """GitHub Releases 최신 태그 조회. 현재 버전보다 높으면 Release, 아니면 None."""

def apply_app_update(release: Release, on_progress: Callable[[str], None]) -> None:
    """§5 절차로 소스 파일 교체 후 앱 재시작. 실패 시 UpdateError."""
```

- 버전 비교는 `packaging.version` 대신 **튜플 비교**(`tuple(int, ...)`)로 처리한다.
  버전 체계가 `0.1.0` 형태로 단순하므로 의존성을 추가할 이유가 없다.
- Releases 조회는 표준 라이브러리 `urllib.request`로 GitHub API 호출
  (`/repos/KIMHeeKwon/Youtube_Downlaod/releases/latest`). 인증 불필요, outbound HTTPS만 사용.

## 4. 최초 실행 감지 및 설정 파일

- 위치: `~/.youtube_downloader.json` (홈 디렉토리).
- **프로젝트 폴더가 아니라 홈에 두는 이유**: 프로젝트 폴더는 업데이트 시 파일 교체 대상이라
  설정이 유실될 수 있다.

```json
{ "tour_shown": true, "skip_version": "v0.2.0" }
```

- `tour_shown`이 없거나 false → 앱 시작 후 투어 자동 실행, 완료/건너뛰기 시 true 기록.
- GUI 하단에 `[사용법 보기]` 버튼을 추가해 언제든 재호출 가능하게 한다.

## 5. 앱 본체 자기 교체 절차 — 유일한 고위험 구간

실행 중인 프로그램이 자기 파일을 교체하는 작업이므로, **교체 범위를 최소화**하고
**되돌릴 수 있게** 만드는 것이 설계의 핵심이다.

### 5.1 교체 대상 범위
| 대상 | 교체 | 이유 |
|------|------|------|
| `*.py`, `static/`, `windows/`, `docs/`, `README.md` | ✅ | 소스 — 수백 KB에 불과 |
| `downloads/` | ❌ | **사용자 데이터** — 절대 건드리지 않음 |
| `.venv/`, `tools/` | ❌ | 무겁고(수백 MB) 재구성 비용이 큼. 의존성 변화는 §5.2의 `uv sync`로 흡수 |
| `~/.youtube_downloader.json` | ❌ | 설정 보존 (§4) |

### 5.2 절차
1. 릴리스 소스 ZIP을 임시 폴더에 다운로드
2. 압축 해제 후 **무결성 확인** — `gui.py`, `downloader.py`, `pyproject.toml` 존재 여부.
   하나라도 없으면 중단하고 아무것도 바꾸지 않는다
3. 현재 소스 파일을 `_backup_<현재버전>/`에 복사
4. 교체 스크립트 생성 (Windows `.bat` / macOS `.sh`)
5. 앱 종료 → 교체 스크립트가 ①파일 복사 ②`uv sync` ③앱 재실행 순으로 수행
6. 스크립트 단계에서 실패하면 백업에서 복원 후 기존 버전으로 재실행

- 앱이 종료된 뒤 별도 프로세스가 교체하는 구조를 쓰는 이유: 실행 중인 파일에 대한
  잠금 문제(특히 Windows)를 원천적으로 피한다.
- `_backup_*` 폴더는 다음 업데이트 성공 시 정리한다.

## 6. README 보강 — 기계적 작업

[[README]] "3단계 — 설치 실행" 절에 보안 경고 대처를 **스크린샷 없이 텍스트로** 추가한다.
현재는 "문제 해결" 표에 한 줄만 있어 처음 겪는 사용자가 설치 도중 이탈할 수 있다.

- Windows SmartScreen: "Windows가 PC를 보호했습니다" 창 → `추가 정보` → `실행` 버튼
- 서명되지 않은 앱인 이유(개인 개발 도구, 코드 서명 인증서 미보유)를 한 줄로 설명해
  사용자가 스스로 판단할 근거를 준다
- `install.bat`은 이미 `-ExecutionPolicy Bypass`로 실행되므로 PowerShell 정책 변경 안내는
  **불필요** — 문서에 넣지 않는다

## 8. 검증 기준

| 항목 | 검증 방법 |
|------|-----------|
| 투어 시각 확인 | macOS에서 직접 실행해 4단계 스포트라이트·말풍선 위치 육안 확인 (D6이 가능하게 한 검증) |
| 투어 CI 회귀 | `gui.py --selftest`에 투어 생성/파괴를 포함해 위젯 오류 없음 확인 |
| 버전 비교 로직 | 단위 테스트 — `0.1.0 < 0.2.0 < 0.10.0` 등 자릿수 함정 포함 |
| 릴리스 파싱 | 단위 테스트 — GitHub API 응답 샘플(JSON 고정 문자열)로 네트워크 없이 검증 |
| 업데이트 실증 | v0.2.0 발행 후 **구버전 설치본**에서 배너 표시 → 업데이트 → 재시작 → 버전 확인 |
| 사용자 데이터 보존 | 업데이트 후 `downloads/` 내용과 설정 파일이 그대로인지 확인 |

## 9. 구현하지 않는 것 (명세 고정)

- 코드 서명 인증서 도입 (D1에서 기각)
- 오프라인 번들 설치본 (D2 — ffmpeg 재배포 시 GPL 의무 발생)
- 앱 본체 무인 자동 갱신 (D3에서 기각)
- 자동 롤백 UI — 실패 시 복원은 교체 스크립트가 자동 수행하며, 사용자가 임의 버전을
  선택하는 기능은 만들지 않는다
