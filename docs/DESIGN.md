# YouTube 고화질 다운로더 — 시스템 설계서

작성일: 2026-07-17
상태: 제안 (구현 전)

---

## 1. 목표 및 범위

### 1.1 목표
YouTube URL을 입력하면 해당 영상을 **가용 최고 화질**로 로컬에 다운로드하는 프로그램.

### 1.2 범위 정의 (MVP)
- 입력: YouTube 영상 URL 1개 (CLI 인자)
- 출력: 최고 화질 영상+음성이 병합된 단일 파일 (MP4 우선)
- 진행률 표시 (다운로드 % / 속도 / ETA)
- 다운로드 경로 지정 옵션

### 1.3 명시적 제외 (MVP에서 하지 않음)
- GUI / 웹 인터페이스 (Phase 2 후보)
- 재생목록/채널 일괄 다운로드 (Phase 2 후보)
- 자막 다운로드, 포맷 변환, 서버 배포

### 1.4 법적 고려사항
YouTube 서비스 약관은 공식 기능 외의 다운로드를 제한한다. 본 도구는
**본인 소유 콘텐츠, CC 라이선스, 개인적·연구적 이용** 범위로 사용을 한정한다.

## 2. 핵심 기술 결정

### 2.1 다운로드 엔진: yt-dlp (직접 구현 대신 채택)

| 대안 | 평가 |
|------|------|
| **yt-dlp** (채택) | YouTube 스트림 추출의 사실상 표준. 시그니처 복호화·포맷 협상·스로틀링 우회를 커뮤니티가 지속 유지보수. Python API 제공 |
| pytube 계열 | YouTube 내부 변경에 대한 대응 속도가 느려 빈번히 깨짐 |
| 직접 구현 (C/Python) | YouTube 내부 API는 비공개·수시 변경. 유지보수 비용이 프로젝트 목적 대비 비합리적 |

**핵심 근거**: YouTube는 고화질(1080p 초과)을 영상/음성 **분리 스트림(DASH)** 으로만
제공한다. "고화질 다운로드"의 본질은 (1) 최적 스트림 선택, (2) 분리 스트림 병합이며,
이 두 문제를 yt-dlp + ffmpeg 조합이 이미 해결한다. 직접 구현은 바퀴의 재발명이다.

### 2.2 병합기: ffmpeg
- bestvideo + bestaudio 분리 스트림을 무손실 병합(스트림 카피, 재인코딩 없음)
- yt-dlp가 ffmpeg를 자동 호출하므로 별도 병합 코드 불필요

### 2.3 언어: Python 3.11+ (uv 관리 가상환경)
- yt-dlp가 Python 네이티브이므로 API 직접 사용 (subprocess 호출보다 진행률 훅·오류 처리가 정밀)
- 시스템 Python 3.9는 건드리지 않고 프로젝트 전용 환경 구성

## 3. 시스템 아키텍처

```
┌─────────────────────────────────────────────────┐
│                  CLI (main.py)                  │
│   argparse: URL, --output-dir, --max-height     │
└───────────────────┬─────────────────────────────┘
                    │
┌───────────────────▼─────────────────────────────┐
│              Downloader (downloader.py)         │
│  1. URL 검증 (youtube.com / youtu.be)           │
│  2. 포맷 선택 전략 수립                          │
│     "bestvideo[ext=mp4]+bestaudio[ext=m4a]      │
│      / bestvideo+bestaudio / best"              │
│  3. yt-dlp API 호출 + progress hook             │
└───────────────────┬─────────────────────────────┘
                    │
        ┌───────────▼───────────┐
        │   yt-dlp (라이브러리)  │──▶ YouTube
        │   스트림 추출/다운로드  │
        └───────────┬───────────┘
                    │ 영상.mp4 + 음성.m4a
        ┌───────────▼───────────┐
        │   ffmpeg (외부 바이너리)│
        │   무손실 병합 (-c copy) │
        └───────────┬───────────┘
                    │
              최종 파일 (제목.mp4)
```

### 3.1 모듈 구성 (파일 2개로 충분)

| 파일 | 책임 | 예상 규모 |
|------|------|-----------|
| `main.py` | CLI 파싱, 진행률 출력, 종료 코드 | ~50줄 |
| `downloader.py` | URL 검증, yt-dlp 옵션 구성, 다운로드 실행 | ~80줄 |

과도한 계층화(플러그인 구조, 추상 인터페이스 등)는 의도적으로 배제한다.
단일 용도 도구에 필요한 최소 구조만 유지한다.

### 3.2 포맷 선택 전략 (고화질 핵심 로직)
```
우선순위 1: bestvideo[ext=mp4][vcodec^=avc1] + bestaudio[ext=m4a]   # 호환성 최우선
우선순위 2: bestvideo + bestaudio                                    # VP9/AV1 포함 최고화질
우선순위 3: best                                                     # 단일 스트림 폴백
```
- 기본값: 가용 최고 해상도 (4K/8K 포함)
- `--max-height 1080` 등으로 상한 지정 가능
- `--codec compat` 옵션 시 H.264 우선(범용 재생 호환), 기본은 최고화질 우선

### 3.3 오류 처리 (실재하는 실패만 다룸)
| 실패 상황 | 처리 |
|-----------|------|
| 잘못된 URL | 즉시 검증 실패 메시지, exit 1 |
| 비공개/삭제/지역제한 영상 | yt-dlp 오류 메시지 전달, exit 1 |
| 네트워크 중단 | yt-dlp 내장 재시도(3회) + `.part` 파일 이어받기 |
| ffmpeg 부재 | 시작 시 사전 점검, 설치 안내 후 종료 |

## 5. 실행 계획 (Goal-Driven)

| 단계 | 작업 | 검증 기준 |
|------|------|-----------|
| 1 | 환경 구성 (ffmpeg, venv, yt-dlp) | `yt-dlp --version`, `ffmpeg -version` 정상 출력 |
| 2 | `downloader.py`: URL 검증 + 포맷 전략 | 유효/무효 URL 단위 테스트 통과 |
| 3 | `main.py`: CLI + 진행률 훅 | 실제 공개 영상 1건 다운로드, 해상도 확인 (`ffprobe`) |
| 4 | 오류 경로 확인 | 무효 URL/비공개 영상에서 명확한 오류 메시지 + exit 1 |

**최종 성공 기준**: `python main.py <URL>` 실행 시 가용 최고 해상도의
단일 MP4 파일이 생성되고, `ffprobe`로 확인한 해상도가 YouTube 웹 표시 최고 화질과 일치.

## 6. 모듈별 라이선스 / 저작권 분석

### 6.1 구성요소별 라이선스

| 구성요소 | 라이선스 | 우리 코드에 미치는 영향 | 문제 여부 |
|----------|----------|--------------------------|-----------|
| **yt-dlp** | Unlicense (퍼블릭 도메인) | 없음. 수정·배포·상용화 모두 자유 | ✅ 없음 |
| **ffmpeg** (Homebrew 빌드) | **GPL v2+** (x264 등 GPL 컴포넌트 포함 빌드) | 외부 프로세스로 호출만 하므로 우리 코드에 GPL이 전파되지 않음. 단, **ffmpeg 바이너리를 프로그램에 동봉·재배포하면 GPL 의무(소스 고지 등) 발생** | ⚠️ 조건부 — 동봉 배포 시 주의 |
| **Python 3.11+** | PSF License (허용적) | 없음 | ✅ 없음 |
| **argparse 등 표준 라이브러리** | PSF License | 없음 | ✅ 없음 |

**설계 반영**: ffmpeg는 동봉하지 않고 사용자 시스템 설치(`brew install ffmpeg`)를
전제로 한다. 이 구조에서는 본 프로젝트 코드를 어떤 라이선스로도 배포 가능하다.

### 6.2 콘텐츠 저작권 (가장 중요한 제약)

| 항목 | 내용 |
|------|------|
| **YouTube 서비스 약관** | 공식 기능(YouTube Premium 오프라인 저장 등) 외의 다운로드를 약관상 금지. 위반은 저작권법 위반이 아닌 **약관 위반**(계정 제재 사유) |
| **다운로드 콘텐츠의 저작권** | 도구가 아닌 **사용 행위**의 문제. 타인 저작물을 무단 복제·재배포하면 저작권 침해 |
| **적법 사용 범위** | ① 본인 업로드 콘텐츠 ② Creative Commons 라이선스 영상 ③ 사적 이용·연구 목적 복제 (한국 저작권법 제30조 사적복제 조항 참조) |
| **도구 자체의 적법성** | yt-dlp류 도구 자체는 배포 금지된 바 없음 (RIAA의 GitHub 삭제 요청이 2020년 기각·복원된 전례). 다만 침해 유도 목적의 배포는 별개 문제 |

**설계 반영**: 본 도구는 개인 연구·본인 콘텐츠 백업 용도로 한정하며,
DRM 우회 기능(영화·멤버십 콘텐츠 등)은 구현하지 않는다.
